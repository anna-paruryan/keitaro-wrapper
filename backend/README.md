# Keitaro tools

Обёртка над рекламным трекером [Keitaro](https://keitaro.io): **создаватор кампаний** и **редактор офферов** в существующей кампании. Работает через Keitaro Admin API.

* **Создаватор**: название + гео (одна или несколько стран) + оффер → кампания с двумя потоками. Первый ловит посетителей из указанных стран и редиректит на Google, второй отправляет всех остальных на выбранный оффер. Домен, группа и источник берутся из API.
* **Редактор**: найти кампанию, посмотреть потоки и офферы с долями и статистикой, добавить или удалить оффер. Доли пересчитываются автоматически и всегда дают ровно 100%.

Стек: FastAPI, SQLAlchemy 2, Alembic, httpx. Фронт без сборки: одна HTML-страница с обычным JavaScript (FastAPI сам её отдаёт).

## Быстрый старт

Нужен Python 3.10+.

```bash
git clone <ссылка-на-репозиторий> keitaro-tools
cd keitaro-tools

python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env                 # Windows: copy .env.example .env
# открой .env и заполни KEITARO_API_KEY и CAMPAIGN_PREFIX (test_фамилия_)

alembic upgrade head                 # создаёт таблицы в БД (миграции)
uvicorn app.main:app --reload        # запуск
```

Открой <http://127.0.0.1:8000>. Документация API (Swagger): <http://127.0.0.1:8000/docs>.

Ключ Admin API: админка Keitaro → Профиль → API ключи.

### Проверка доступа к Keitaro

Перед первым запуском можно проверить, что трекер отвечает как ожидается (скрипт только читает, ничего не создаёт):

```bash
python scripts/check_keitaro.py
```

Он покажет офферы, домены, группы, источники, имя фильтра по стране, форму потока и отчёта. Если что-то названо иначе, это видно сразу.

## Как это работает

### Создаватор кампаний

`POST /api/campaigns` с `{name, geo, offer_id}` делает в Keitaro:

| Что | Как настроено |
|---|---|
| Кампания | имя `<CAMPAIGN_PREFIX><название>`, ротация потоков «по позиции», модель затрат CPC, стоимость 0 USD, «из параметра cost», случайный идентификатор (alias) |
| Домен, группа, источник | выбираются из API (по умолчанию домен из `KEITARO_DOMAIN`, группа и источник `FORTESTS`), в форме можно сменить |
| Поток 1 | позиция 1, фильтр «страна — принимать» (все указанные страны), действие: HTTP-редирект на `GOOGLE_REDIRECT_URL` |
| Поток 2 | позиция 2, без фильтров (ловит всех остальных), схема «офферы», выбранный оффер с долей 100% |

* Гео принимает несколько стран: `MX,AU,RO` (регистр и разделители не важны).
* Всё проверяется до обращения к Keitaro: формат гео, существование оффера, наличие группы и источника.
* Если второй поток не создался, кампания из первого шага удаляется, чтобы в трекере не оставалось недоделанных кампаний.
* Созданные кампании сохраняются в локальной БД (история на странице + пометка «создана здесь» в редакторе).

### Редактор кампании

* Список кампаний с поиском по ID и названию. Переключатель «только test_фамилия_…» показывает только свои кампании.
* Для каждого потока: фильтры, редирект или таблица офферов с долей, кликами, уникальными, конверсиями и доходом.
* **Добавить оффер**: поиск по ID или названию (Keitaro не умеет искать офферы, поэтому список кэшируется на `OFFERS_CACHE_TTL` секунд и фильтруется на сервере).
* **Удалить оффер**: с подтверждением. Последний оффер потока удалить нельзя (поток без офферов не отправит трафик).
* **Поделить поровну**: выравнивает доли.
* **Правила пересчёта долей** (`app/shares.py`): сумма всегда ровно 100, целые числа (метод наибольшего остатка).
  * Было поровну: остаётся поровну (`50/50` + оффер → `34/33/33`, `34/33/33` − оффер → `50/50`).
  * Были свои пропорции (например `80/20`): они сохраняются, новый оффер получает «среднюю» долю.
* После каждого действия карточка перечитывается из Keitaro, поэтому на экране всегда то, что реально лежит в трекере.
* Журнал правок (кто что добавил или удалил и как изменились доли) хранится в БД и виден под карточкой кампании.
* **Защита общего трекера**: если задан `CAMPAIGN_PREFIX`, менять можно только кампании с этим префиксом, чужие можно только смотреть.
* Если отчёт Keitaro недоступен, редактор продолжает работать: офферы и доли показываются верно, а над таблицей появляется предупреждение.

## Настройки (`.env`)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `KEITARO_URL` | | адрес трекера (`https://tlgk.host`; `/admin` на конце можно оставить) |
| `KEITARO_API_KEY` | | ключ Admin API |
| `CAMPAIGN_PREFIX` | пусто | префикс названий (`test_ivanov_`), добавляется автоматически |
| `KEITARO_GROUP_NAME` | `FORTESTS` | группа кампаний по умолчанию (поиск по названию) |
| `KEITARO_SOURCE_NAME` | `FORTESTS` | источник по умолчанию |
| `KEITARO_DOMAIN` | пусто | часть названия домена; если пусто, берётся первый из API |
| `GOOGLE_REDIRECT_URL` | `https://www.google.com` | куда редиректит первый поток |
| `DATABASE_URL` | `sqlite:///./data/app.db` | база приложения |
| `OFFERS_CACHE_TTL` | `300` | кэш списка офферов, секунд |
| `COUNTRY_FILTER_NAME` | пусто | имя фильтра по стране; по умолчанию определяется через API |

## База данных и миграции

Таблицы: `campaigns` (история созданных кампаний) и `offer_changes` (журнал правок офферов). Схема управляется Alembic, `Base.metadata.create_all` в приложении не используется.

```bash
alembic upgrade head                              # применить все миграции
alembic downgrade -1                              # откатить последнюю
alembic revision --autogenerate -m "описание"     # новая миграция после изменения app/models.py
alembic current                                   # текущая версия схемы
```

По умолчанию SQLite (файл `data/app.db` создаётся сам). Для PostgreSQL:

```bash
pip install "psycopg[binary]"
# в .env:
# DATABASE_URL=postgresql+psycopg://user:password@localhost:5432/keitaro_tools
alembic upgrade head
```

Если забыть выполнить миграции, при старте в логе появится подсказка.

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/health` | сервер жив, настроен ли Keitaro |
| GET | `/api/meta` | префикс, домены, группы, источники и выбор по умолчанию |
| GET | `/api/offers?q=&limit=` | поиск офферов по ID или названию |
| POST | `/api/campaigns` | создать кампанию `{name, geo, offer_id, domain_id?, group_id?, traffic_source_id?}` |
| GET | `/api/campaigns?q=&mine=` | список кампаний Keitaro |
| GET | `/api/campaigns/{id}` | кампания: потоки, офферы, доли, статистика |
| POST | `/api/campaigns/{id}/streams/{stream_id}/offers` | добавить оффер `{offer_id}` |
| DELETE | `/api/campaigns/{id}/streams/{stream_id}/offers/{offer_id}` | удалить оффер |
| POST | `/api/campaigns/{id}/streams/{stream_id}/equalize` | поделить доли поровну |
| GET | `/api/campaigns/{id}/changes` | журнал правок |
| GET | `/api/history` | последние созданные кампании |

Ошибки приходят в виде `{"detail": "понятный текст"}`: 422 неверные данные, 404 не найдено, 409 конфликт, 403 чужая кампания, 502 ошибка Keitaro (с его текстом), 503 Keitaro не настроен.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Keitaro в тестах заменён эмулятором (`tests/conftest.py`), поэтому тесты работают без доступа к трекеру. Покрыто: создание кампании (поля, оба потока, фильтр по гео, откат при ошибке), редактор (добавление, удаление, пересчёт долей, защита, статистика и её отказ), расчёт долей, клиент (ошибки, URL), а также применение миграций с нуля и их совпадение с моделями.

## Структура

```
app/
  main.py        приложение FastAPI, обработчики ошибок, раздача фронта
  api.py         маршруты /api/*
  services.py    логика: создание кампании, редактор, статистика
  keitaro.py     клиент Admin API (единственное место, которое знает про HTTP Keitaro)
  shares.py      расчёт долей офферов
  models.py      модели SQLAlchemy
  db.py, config.py, schemas.py
migrations/      Alembic
scripts/check_keitaro.py   проверка доступа к трекеру (только чтение)
tests/
```

## Допущения

Публичный справочник Admin API ([admin-api.docs.keitaro.io](https://admin-api.docs.keitaro.io)) описывает методы, а точные названия полей зависят от версии трекера. Поэтому в коде заложено:

* **Фильтр по стране**: имя берётся из `GET /stream_filters` (`country`, при отсутствии `country_code`). Можно задать вручную через `COUNTRY_FILTER_NAME`.
* **Потоки кампании**: `GET /campaigns/{id}/streams`; если трекер отвечает 404/405, используется `GET /streams?campaign_id=`.
* **Статистика**: отчёт `POST /report/build` по кампании, группировка по потоку и по офферу. Если трекер не принимает интервал или набор метрик, запрос повторяется с запасными вариантами (только клики, явные даты).
* **Группы**: из `GET /groups` берутся только группы кампаний (по полю `type`).
* **Изменение офферов**: `PUT /streams/{id}` с одним полем `offers`. Остальные настройки потока не трогаются.

Всё, что связано с форматом Keitaro, сосредоточено в `app/keitaro.py` и в начале `app/services.py`. `python scripts/check_keitaro.py` показывает реальные ответы трекера.
