# Логика редактора

Подробности, которые не нужны для запуска, но объясняют поведение редактора.

## Черновик и цвета

Правки не пишутся в Keitaro сразу. Они копятся в нашей базе (черновик), а в Keitaro уходят только по **Push to KT**. Поэтому после обновления страницы (F5) жёлтые потоки остаются жёлтыми.

| Вид | Значение |
|---|---|
| Белая карточка | в карточке то же, что и в Keitaro |
| Жёлтая карточка, тег Unpublished | есть правки, которых в Keitaro ещё нет |
| Строка с тегом `new` | оффер добавлен, в Keitaro его ещё нет |
| Серая зачёркнутая строка, тег `removed` | оффер убран; он остаётся в архиве, его можно вернуть |

## Действия

| Действие | Что происходит |
|---|---|
| Fetch Streams | потоки и офферы читаются из Keitaro и сверяются с базой. В Keitaro ничего не пишется. Оффер, который мы знали, а в Keitaro его уже нет (или он выключен), показывается серым |
| Add | оффер добавляется в черновик, доли пересчитываются |
| Remove | строка серая, доля 0%, остальные доли пересчитываются |
| Bring Back | серый оффер возвращается в черновик |
| Pin | закрепляет текущую долю, сам по себе ничего не пересчитывает |
| Push to KT | единственное место, где мы пишем в Keitaro: берётся текущий поток, в нём заменяется список `offers`, поток отправляется обратно (`PUT /streams/{id}`). Убранный оффер пропадает из списка |
| Cancel | добавленные офферы удаляются из черновика, убранные возвращаются, доли как в Keitaro |

Поток без офферов (редирект на Google) показывается просто как поток: его содержимое мы не разбираем и не меняем.

## Правила долей

Реализованы в `backend/app/shares.py` (функция `distribute`).

* Доли целые, сумма ровно 100 (метод наибольшего остатка, лишний 1% достаётся верхнему офферу).
* Закреплённые доли стоят на месте, остальные офферы делят остаток поровну.
* Пример: четыре оффера по 25%, закрепили один и убрали другой. Остальные два делят 75%: получается 38% и 37%.
* Если закреплённые доли не оставляют места другим офферам, правка отклоняется с понятным сообщением, ничего не меняется.
## Защиты

* Меняются только кампании с префиксом `CAMPAIGN_PREFIX`.
* Push отклоняется, если после последнего Fetch состав офферов в Keitaro изменили вручную. Нужно сделать Fetch заново, иначе можно затереть чужие правки.
* Поток нельзя опубликовать без активных офферов или если доли не дают 100.
* Каждый Push записывается в журнал (`offer_changes`, метод `GET /api/campaigns/{id}/changes`).
## Что проверено вручную на tlgk.host

Автотесты используют эмулятор Keitaro и не доказывают, что настоящий трекер примет те же запросы, поэтому важное проверено руками:

* создание кампании через Swagger и через интерфейс: два потока, фильтр по стране, редирект на Google, оффер во втором потоке;
* Fetch: потоки и офферы совпадают с Keitaro;
* Add + Push: оффер появляется в потоке Keitaro, доли совпадают с интерфейсом;
* Remove + Push: оффер исчезает из Keitaro, в редакторе остаётся серым; Bring Back + Push возвращает его;
* оффер, удалённый вручную в Keitaro, после Fetch становится серым, оставшиеся доли показываются как в Keitaro;
* Pin: закреплено 34%, второй оффер убран, оставшийся получает 66%; после Bring Back снова 34 / 33 / 33.
## Допущения

* Keitaro сам не пересчитывает доли: если убрать оффер вручную в Keitaro, остальные доли остаются как были (сумма может быть не 100). Редактор показывает их как есть и пересчитывает, только когда вы меняете поток.
* Публичное описание API ([admin-api.docs.keitaro.io](https://admin-api.docs.keitaro.io)) не полностью совпадает с поведением конкретной версии трекера. Всё, что зависит от формата Keitaro, собрано в `backend/app/keitaro.py` и в начале `backend/app/services.py`. Скрипт `python scripts/check_keitaro.py` показывает реальные ответы трекера.
* Домен, группа и источник: форма показывает то, что отдаёт API (блок «Why these values?»). Кампании создавались с группой из API и без источника, а домен подставил сам Keitaro.
## Ошибки API

Ошибки приходят как `{"detail": "понятный текст"}`: 422 неверные данные, 404 не найдено, 409 конфликт, 403 чужая кампания, 502 ошибка Keitaro (с его текстом), 503 Keitaro не настроен. Фронтенд показывает этот текст во всплывающем уведомлении.
